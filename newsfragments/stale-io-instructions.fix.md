Reconfiguring the hardware interface no longer corrupts the heap. The read and write instruction vectors were appended to on every configure cycle and never cleared, while the sum buffers they index were resized to the current layout count. A second configure that resolved fewer symbols than the first, which is exactly what a link drop or a reflashed PLC produces now that unresolved layouts are dropped from the buffers, left instructions carrying offsets computed against the larger buffer: the reader thread then read past the end of the response buffer and write() packed a command past the end of the request buffer, on the control loop. Both instruction vectors, both sum buffers and the read cache are now rebuilt from scratch on every configure. (stale-io-instructions)
