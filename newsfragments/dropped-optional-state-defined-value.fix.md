State interfaces backed by a dropped optional PLC symbol now hold a defined value instead of NaN. on_configure dropped an unresolved optional symbol from the sum buffers but never wrote its state interfaces, and a state handle with no declared initial_value starts as NaN, so a downstream consumer testing value != 0.0 read the absent state as asserted and inverted every gate it protected. Those interfaces are now pinned to 0.0 at configure, while a declared initial_value interface parameter keeps its value, which the framework already applies to the handle at export. The warning no longer claims an initial value exists when none was declared. (dropped-optional-state-defined-value)
