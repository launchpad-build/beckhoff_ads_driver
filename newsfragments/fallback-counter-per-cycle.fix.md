`ads_fallback_activations` now counts only interfaces that something has commanded at least once, so a real dropout registers and an interface nobody drives stays quiet. It could not do that before: `write()` clears every command interface to NaN after packing, and a controller only writes the interfaces its most recent command message named, so any interface nothing had ever commanded counted a fallback on every cycle. Measured on the LMCF gantry it added exactly 4.000 per cycle after an engage, falling to exactly 1.000 once a message named four of the five gpio commands, and reached 409864 against 112152 write transactions. Two counters join it: `ads_fallback_activations_per_cycle`, because the rate is what tells you when a dropout started and stopped, and `ads_never_commanded_interfaces`, so a quiet interface is legible in one place instead of inflating the dropout count. An interface that stops being commanded after having been commanded also logs a throttled warning naming itself. Nothing about what is written to the PLC changes. (fallback-counter-per-cycle)
