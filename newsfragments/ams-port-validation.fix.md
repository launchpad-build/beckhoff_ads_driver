The plc_ams_port hardware parameter is now validated instead of silently truncated. std::stoul narrowed to uint16_t wrapped any value above 65535 to a different port, so a typo connected to the wrong ADS port rather than failing configure. A port outside 1 to 65535, or with trailing characters, now fails configure with a message naming the value. Upper-casing the PLC_type string also casts each character through unsigned char first, since ::toupper on a plain char is undefined for negative values. This change adds the package's first unit tests and the gtest wiring to run them under colcon test. (ams-port-validation)
