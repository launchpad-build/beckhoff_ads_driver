A dropped ADS connection no longer segfaults the hardware interface. The reader and writer threads dereference ads_device_ on every round-trip without a lock, and on_configure destroyed the old device when it assigned the new one without joining them first, so a thread was left calling a method on a freed AdsDevice whose local AMS port had already been released. Any failure that made read() or write() return ERROR reached that state, because the error transition goes straight to on_error, which was not overridden, so neither on_deactivate nor on_shutdown ran and the threads kept hammering a component the controller manager had given up on. on_configure now joins both threads before touching the device, on_error tears the link down the same way on_shutdown does, and the invariant that every write to ads_device_ is preceded by a join is written down where the member is declared.
