A momentary ADS comms drop no longer deactivates every controller. read() and write() returned ERROR on the first failed round-trip, so one hiccup, one reprogram or one symbol the PLC rejected at runtime made the controller manager cascade-deactivate the whole hardware component and take ros2_control_node with it, forcing a relaunch. A failure now only surfaces once an outage outlives a grace window, configurable through comms_outage_grace_ms and defaulting to 1000 ms, and the last cached values are held meanwhile. A per-item symbol error is held at its last value and logged rather than faulting the component, while every item failing at once is still treated as an outage so the window backstops a program swap. Setting the parameter to 0 restores the previous fail-on-first-cycle behaviour. (ads-comms-outage-grace)
