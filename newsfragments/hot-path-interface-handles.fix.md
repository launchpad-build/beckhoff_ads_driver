read() and write() no longer access interface values by name. The string-keyed set_state, get_command and set_command overloads do an unordered_map lookup per call, then take the handle's shared mutex with a blocking wait and throw on failure, and their own documentation marks them as not real-time safe. The interface handle pointers are now resolved once at configure, stored in the read and write instructions, and the cycle uses the non-blocking handle accessors: no allocation, no string hashing, no lock wait and no throwing path on the control loop. A non-blocking access that loses the try-lock race skips that field for the cycle, which the hold-last packing already tolerates. (hot-path-interface-handles)
