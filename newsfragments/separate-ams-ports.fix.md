The reader and writer threads no longer share one local AMS port behind a mutex. A read round-trip held the port for its whole duration, so a setpoint arriving inside that window queued behind it and delivery latency was bimodal; the reader's best-effort yield could not fix that, since std::mutex has no fairness. Each direction now has its own AdsDevice, which opens its own local AMS port on the shared process-wide local net id with a refcounted route, so the two round-trips never contend and the shared I/O mutex is gone. The PLC still sees a single AMS net id, so this does not recreate the two-clients-one-identity crash; symbol handles are acquired and released through the device that will use them.
