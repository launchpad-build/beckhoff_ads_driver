## 1.5.0 (2026-09-25)

### Features

- An optional `heartbeat_plc_symbol` hardware parameter makes the interface advance a UDINT counter on the PLC on every write. A PLC-side watchdog can then tell a live control stack from one that died mid-move, and hold the machine instead of driving to the last target it received. The interface owns the counter rather than a controller, so it also stops when the controller manager stalls or the writer thread wedges. Absent parameter leaves the behaviour unchanged. Watch the counter for movement, never for a step of one: the writer coalesces, so it jumps. (ads-link-heartbeat) (ads-link-heartbeat)
- The ADS request timeout now defaults to 100 ms instead of the library's 5000 ms. A blocking ADS call bounds how long stopping the I/O threads can stall on teardown, and how long a dead link can sit undetected inside one round-trip, so five seconds suited neither. The ads_request_timeout_ms hardware parameter overrides the value and 0 keeps the library default. (ads-request-timeout) (ads-request-timeout)
- The interface now publishes its ADS transaction behaviour through the controller manager's introspection topic: read and write round-trip times, transaction counts, coalesced writes, read and write failures, command-fallback activations and the heartbeat value. Coalescing a write is the intended policy, since only the newest setpoints matter, but the rate it happens at is how you tell whether the link keeps up with the control loop, and it was invisible. The reader also yields the shared AMS port to a waiting setpoint, because a read started first holds the port for a whole round trip and reads tolerate being a cycle late where setpoints do not. (ads-transaction-statistics) (ads-transaction-statistics)
- A per-item read failure can no longer freeze a joint's feedback forever while the component reports healthy. Only all-items-failed tripped the outage path; a single invalidated handle held its state interface at the last value indefinitely, which is deliberate for telemetry and wrong for a joint position. State interfaces can now be critical: a critical item whose per-item read keeps failing beyond the grace window hard-faults the component. Joint position and velocity interfaces are critical by default; gpio, sensor and other joint interfaces are not. A critical interface parameter of true or false overrides the default either way, and the state_interface_PLC xacro macro passes it through. (critical-state-items) (critical-state-items)
- The I/O threads now run with real-time scheduling by default. Both were plain std::thread under SCHED_OTHER, so any wake delay after the write notify let a newer buffer overwrite the pending one, a coalesced and therefore lost setpoint. Both threads default to SCHED_FIFO at priority 50 and can be tuned or disabled through the io_thread_scheduling_policy (fifo, rr, other or inherit), io_thread_priority and io_thread_cpu_affinity hardware parameters. When the process lacks the real-time capability the interface warns, names the fix and carries on with normal scheduling. (io-thread-real-time-scheduling) (io-thread-real-time-scheduling)
- The outage handling now suits a motion stream. The grace window default drops from 1000 ms to 100 ms, matching the PLC's own ROS link watchdog, so ROS surfaces a dead link no later than the machine stops; comms_outage_grace_ms still overrides it. A hard fault now latches by default instead of self-clearing on the next good round-trip, so a recovered link cannot silently resume the stream with a position step of up to velocity times outage; the component faults, restarts deliberately and reseeds. outage_behaviour=resume restores the old self-clearing behaviour for hold-last telemetry and GPIO stacks. read() also stops hiding staleness: once the published sample is older than read_staleness_timeout_ms, 100 ms by default and raised to three poll periods under paced reading, read() returns an error instead of frozen feedback that reports healthy; 0 disables the check. (outage-window-latch-staleness) (outage-window-latch-staleness)
- Optional `setpoint_sequence_plc_symbol` and `setpoint_time_plc_symbol` hardware parameters annotate every streamed write with a UDINT sequence number and an LREAL steady-clock timestamp in seconds. Both are packed into the same sum-write transaction as the setpoints they describe, so they change if and only if the accompanying targets are new. A PLC interpolating between streamed samples can then detect a genuinely new setpoint even when consecutive setpoints are identical, and place it on the time axis free of ADS transport jitter. The sequence counts controller write cycles, not transmitted buffers: a coalesced buffer shows up as a jump, telling the PLC how many updates it lost. Wrapping at the 32-bit boundary is expected. Absent parameters leave the behaviour unchanged. (setpoint-sequence-timestamp) (setpoint-sequence-timestamp)
- The write statistics now expose the queueing delay a setpoint suffers before its send even starts. The round-trip time was measured once the writer already held the connection, so the wait between write() handing a buffer over and the writer picking it up, the part of delivery latency that actually reaches the PLC late, was invisible. Each pending buffer is stamped at handoff; ads_write_buffer_age_ms publishes its age when the send starts and ads_write_handoff_latency_ms the full handoff-to-send-complete latency. (write-handoff-latency-stats) (write-handoff-latency-stats)
- The `command_interface_PLC` and `state_interface_PLC` xacro macros pass through the new `command_fallback` and `optional` interface parameters. Both are omitted when left empty, so existing descriptions produce byte-identical output. (xacro-interface-params) (xacro-interface-params)

### Fixes

- on_activate no longer returns before the first PLC sample lands. It returned immediately, so early read() calls published NaN into any controller that samples state on activation. Activation now waits, bounded by activation_first_sample_timeout_ms with a 1000 ms default, for the first good sample; it fails cleanly on timeout or on a link fault during the wait, and 0 restores the old return-immediately behaviour. (activation-waits-first-sample) (activation-waits-first-sample)
- A momentary ADS comms drop no longer deactivates every controller. read() and write() returned ERROR on the first failed round-trip, so one hiccup, one reprogram or one symbol the PLC rejected at runtime made the controller manager cascade-deactivate the whole hardware component and take ros2_control_node with it, forcing a relaunch. A failure now only surfaces once an outage outlives a grace window, configurable through comms_outage_grace_ms and defaulting to 1000 ms, and the last cached values are held meanwhile. A per-item symbol error is held at its last value and logged rather than faulting the component, while every item failing at once is still treated as an outage so the window backstops a program swap. Setting the parameter to 0 restores the previous fail-on-first-cycle behaviour. (ads-comms-outage-grace) (ads-comms-outage-grace)
- A dropped ADS connection no longer segfaults the hardware interface. The reader and writer threads dereference ads_device_ on every round-trip without a lock, and on_configure destroyed the old device when it assigned the new one without joining them first, so a thread was left calling a method on a freed AdsDevice whose local AMS port had already been released. Any failure that made read() or write() return ERROR reached that state, because the error transition goes straight to on_error, which was not overridden, so neither on_deactivate nor on_shutdown ran and the threads kept hammering a component the controller manager had given up on. on_configure now joins both threads before touching the device, on_error tears the link down the same way on_shutdown does, and the invariant that every write to ads_device_ is preceded by a join is written down where the member is declared. (ads-device-lifetime) (ads-device-lifetime)
- The plc_ams_port hardware parameter is now validated instead of silently truncated. std::stoul narrowed to uint16_t wrapped any value above 65535 to a different port, so a typo connected to the wrong ADS port rather than failing configure. A port outside 1 to 65535, or with trailing characters, now fails configure with a message naming the value. Upper-casing the PLC_type string also casts each character through unsigned char first, since ::toupper on a plain char is undefined for negative values. This change adds the package's first unit tests and the gtest wiring to run them under colcon test. (ams-port-validation) (ams-port-validation)
- Command interfaces now choose what is sent on a cycle where no controller wrote one, through a `command_fallback` interface parameter of `hold_last`, `mirror_state` or `zero`. The mirror-state path never worked: command interfaces were linked to their state interfaces after the write buffers had already resolved the fallbacks out of that link, so the map was always empty and every interface silently held its last value. Linking now happens first, the lookup is guarded against a missing pair, and `hold_last` stays the default so existing behaviour is unchanged. `zero` suits a velocity command, where holding the last value keeps a dead controller's feed-forward alive. Fallback activations are counted. (command-fallback-policy) (command-fallback-policy)
- State interfaces backed by a dropped optional PLC symbol now hold a defined value instead of NaN. on_configure dropped an unresolved optional symbol from the sum buffers but never wrote its state interfaces, and a state handle with no declared initial_value starts as NaN, so a downstream consumer testing value != 0.0 read the absent state as asserted and inverted every gate it protected. Those interfaces are now pinned to 0.0 at configure, while a declared initial_value interface parameter keeps its value, which the framework already applies to the handle at export. The warning no longer claims an initial value exists when none was declared. (dropped-optional-state-defined-value) (dropped-optional-state-defined-value)
- `ads_fallback_activations` now counts only interfaces that something has commanded at least once, so a real dropout registers and an interface nobody drives stays quiet. It could not do that before: `write()` clears every command interface to NaN after packing, and a controller only writes the interfaces its most recent command message named, so any interface nothing had ever commanded counted a fallback on every cycle. Measured on the LMCF gantry it added exactly 4.000 per cycle after an engage, falling to exactly 1.000 once a message named four of the five gpio commands, and reached 409864 against 112152 write transactions. Two counters join it: `ads_fallback_activations_per_cycle`, because the rate is what tells you when a dropout started and stopped, and `ads_never_commanded_interfaces`, so a quiet interface is legible in one place instead of inflating the dropout count. An interface that stops being commanded after having been commanded also logs a throttled warning naming itself. Nothing about what is written to the PLC changes. (fallback-counter-per-cycle) (fallback-counter-per-cycle)
- The dropped-command warning moves out of the write() packing loop. Each affected interface evaluated a throttled warning per cycle inside the per-item loop; the loop now only notes the first affected interface and one throttled warning after the loop reports the count with that name as the example. Nothing about what is written to the PLC changes. (fallback-warning-off-packing-loop) (fallback-warning-off-packing-loop)
- read() and write() no longer access interface values by name. The string-keyed set_state, get_command and set_command overloads do an unordered_map lookup per call, then take the handle's shared mutex with a blocking wait and throw on failure, and their own documentation marks them as not real-time safe. The interface handle pointers are now resolved once at configure, stored in the read and write instructions, and the cycle uses the non-blocking handle accessors: no allocation, no string hashing, no lock wait and no throwing path on the control loop. A non-blocking access that loses the try-lock race skips that field for the cycle, which the hold-last packing already tolerates. (hot-path-interface-handles) (hot-path-interface-handles)
- The PLC no longer receives values nothing commanded. The sum-write buffer is zero-filled when built, the packing loop skips fields no controller has written, and the whole buffer was transmitted anyway, so from activation until the first command every write forced every symbol to zero, which for a position setpoint is a commanded move to the origin. A write item is now transmitted only once every one of its fields holds a provided value: a controller command, an applied fallback, or a declared initial_value, which the framework applies to the command handle at export and the buffer is seeded from at configure. Items still waiting for a first value are left out of the transmitted request entirely. Unmapped elements of a partially mapped PLC array still transmit zero once their item is included, as before. (never-commanded-not-transmitted) (never-commanded-not-transmitted)
- A PLC symbol the runtime does not have no longer takes the whole stack down. An unresolved handle used to stay in the sum buffers with a zero handle, so every round trip returned a per-item error, `read()` faulted the component on the first cycle and the controller manager cascade-deactivated every controller. Interfaces can now declare `optional="true"`, which drops the symbol from the buffers with a warning and leaves those interfaces at their initial value; a required symbol that is missing fails `on_configure` instead, before anything is running. This is what lets a bringup that reads new diagnostics be deployed against a PLC that has not been flashed yet. (optional-plc-symbols) (optional-plc-symbols)
- The reader and writer threads no longer share one local AMS port behind a mutex. A read round-trip held the port for its whole duration, so a setpoint arriving inside that window queued behind it and delivery latency was bimodal; the reader's best-effort yield could not fix that, since std::mutex has no fairness. Each direction now has its own AdsDevice, which opens its own local AMS port on the shared process-wide local net id with a refcounted route, so the two round-trips never contend and the shared I/O mutex is gone. The PLC still sees a single AMS net id, so this does not recreate the two-clients-one-identity crash; symbol handles are acquired and released through the device that will use them. (separate-ams-ports) (separate-ams-ports)
- Reconfiguring the hardware interface no longer corrupts the heap. The read and write instruction vectors were appended to on every configure cycle and never cleared, while the sum buffers they index were resized to the current layout count. A second configure that resolved fewer symbols than the first, which is exactly what a link drop or a reflashed PLC produces now that unresolved layouts are dropped from the buffers, left instructions carrying offsets computed against the larger buffer: the reader thread then read past the end of the response buffer and write() packed a command past the end of the request buffer, on the control loop. Both instruction vectors, both sum buffers and the read cache are now rebuilt from scratch on every configure. (stale-io-instructions) (stale-io-instructions)
- Joint velocity command interfaces now default to a zero command fallback. hold_last was the default for every command interface, so a controller unloading mid-move left its last velocity target being re-sent as a live feed-forward every cycle. A joint velocity interface with no explicit command_fallback now falls back to zero and logs that choice at configure; declaring hold_last or mirror_state overrides it. Position, gpio and every other interface keep hold_last as before. (velocity-fallback-zero-default) (velocity-fallback-zero-default)
- read() can no longer publish a torn snapshot. The reader thread stored decoded values one atomic slot at a time while the control loop read them, so one joint's position could come from a newer sample than another's, or than its own velocity, skewing a pair by up to a read cycle. The reader now publishes each whole decoded sample through a wait-free triple buffer, so every state interface in a control cycle comes from the same SUM read. Each sample carries a steady-clock stamp and the new ads_read_sample_age_ms introspection value exposes how old the published state is. (whole-sample-read-snapshot) (whole-sample-read-snapshot)
- Configure now warns when a joint position or velocity interface declares a 32-bit REAL PLC type. A float carries roughly seven significant digits, so a millimetre-scale gantry position streamed through one quietly loses precision the control loop then chases; the warning names the interface and points at LREAL. (warn-32-bit-joint-types) (warn-32-bit-joint-types)

## 1.3.0 (2026-07-01)

### Features

- Move the blocking ADS SUM read and write off the control loop onto dedicated worker threads. `write()` marshals the latest command buffer, hands it to a writer thread, and returns. The writer sends only the newest buffer, so no backlog builds. A reader thread runs the SUM read and caches the result for a non-blocking `read()`. The control-loop cycle time no longer tracks PLC or network latency. This clears the controller-manager overrun warnings at high update rates. An optional `read_poll_period_ms` hardware parameter paces the reader to cap PLC load.

### Fixes

- Release cached PLC symbol handles while the ADS device is still alive, before shutdown resets it or reconfigure replaces it. Each handle deleter calls `DeleteSymbolHandle` through the device. Releasing a handle after the device is gone dereferenced freed memory and segfaulted on Ctrl-C.
